# TLK1221 DXH_AI — 8B/10B 设计确认与验证报告（第二轮）

> 日期：2026-08-10 ｜ 工具：ModelSim SE-64 10.6d ｜ 基线：XAPP1112、PG047、IEEE 802.3 Tables 36-1a..36-2
> 范围：本地 RTL `encode_8b10b.v`、`decode_8b10b.v`（及关联 `tlk1221_phy_if.v`、`tlk1221_axis_top.v`）的 8B/10B 设计确认、缺陷修复与仿真验证。

---

## 1. 基线与确认方法

以 XAPP1112《Parameterizable 8b/10b Decoder》、PG047《1G/2.5G Ethernet PCS/PMA》及 IEEE 802.3 码表为权威基线（详见《8B10B编解码设计方案.md》）。确认手段：

1. **静态对照**：将本地 RTL 码表、RD 状态机、K 字符处理、disparity 检查与基线逐项比对。
2. **参考实现生成**：用 Python 按标准码表 + 分区 Widmer 算法生成编解码器，自检（popcount∈{4,5,6}、无 5 连续位、单射往返、K28.5=0x0FA/0x305 逗号）后产出 Verilog。
3. **ModelSim 仿真**：`tb_8b10b_codec`（5 项测试）+ `tb_tlk1221_full`（CDC+环回）。

## 2. 第一轮确认发现的缺陷（8B/10B 相关）

| ID | 严重度 | 位置 | 缺陷 |
|----|--------|------|------|
| 8B10B-1 | 严重 | `encode_8b10b.v` K28.5 | K28.5 的 4b 硬编码为 `0101`（RD+ 也发 `0101`），且整体使 K28.5 = 0x0F5，**不含标准逗号序列 `0011111`**，远端 comma 检测无法锁定 → 链路无法同步。 |
| 8B10B-2 | 严重 | `encode_8b10b.v` 5B/6B、3B/4B | 码表非标准：D.28 与 K.28 共用 `001111/110000`（标准 D.28 应为 `001110`）；D.19–D.22 等为单 −2 码，在 RD− 下产生非法不一致性；3B/4B D.x.0=1010（标准 1011）。导致 RD 漂移与真实数据损坏。 |
| 8B10B-3 | 严重 | `decode_8b10b.v` 译码表 | 6b 译码 case 存在重复/歧义项（`011100` 同时匹配 D.15 与 D.18 等），Verilog 取首匹配 → D.18→D.15、D.30→D.2、D.22→D.0 数据损坏；K28.5 被误解为 K28.0。 |
| 8B10B-4 | 高 | `encode_8b10b.v` disp_flip | 多处 RD 翻转标志错误（D.3/D.18–D.22 缺翻转，D.x.0 多余翻转，D.x.5/D.x.6 缺翻转等），RD 状态机失步。 |
| LINK-1 | 严重 | `tlk1221_phy_if.v` IDLE_WORD | `IDLE_WORD=10'h0BC` 非任何合法 K 字符，comma 检测永不触发，链路死锁。 |
| LINK-2 | 中 | `tlk1221_phy_if.v` 空闲 | 空闲恒定发送单一 K28.5（±2），RD 持续单向漂移 → disp_err。 |
| CDC-1 | 中/高 | `tlk1221_phy_if.v` | `tlk_rx_sync`（恢复时钟域）在 `clk_phy_tx` 域 FSM 中直接采样，无同步器。 |
| CDC-2 | 低/中 | `tlk1221_axis_top.v` | 恢复时钟 `PL_SFP_RBC0` 用 `assign` 直通，未走全局缓冲。 |

第一轮实测：codec pass=177 fail=98 rd_violations=116（D.18→0x0f、D.30→0x02、D.22→0x00 等真实损坏）；全顶层 code/disp_err=1。

## 3. 本轮修复

1. **整体替换 8B/10B 码表为 IEEE 802.3 标准码表**（8B10B-1/2/3/4 一并解决）：由 `scripts/gen_8b10b.py` 按权威码表 + 分区 Widmer 算法（4b 子块按 6b 输出 RD 选列）生成 `encode_8b10b.v` / `decode_8b10b.v`。
   - 编码器：`case({curr_rd_state,kin,din})` → dout + code_err；RD 翻转由 `popcount(dout)!=5` 推导。
   - 解码器：1024 项 flat 反查表（标准码表单射，RD 无关），code_err 兜底；disp_err 由整符号 popcount 与 RD 校验。
   - K28.5 = **0x0FA / 0x305**（标准逗号）；D.28 用 `001110`，与 K.28 `001111` 严格分离；D.x.7 按 P7/A7 规则避免 5 连续位。
2. **IDLE_WORD 修复（LINK-1/2）**：`tlk1221_phy_if.v` IDLE 改为 K28.5 逗号 0x0FA，并按拍交替 0x0FA/0x305 维持 RD 直流平衡。
3. **CDC-1 修复**：在 `clk_phy_tx` 域对 `tlk_rx_sync` 加 3 级同步器，phy_tx FSM 改用同步后信号。
4. **CDC-2 修复**：`tlk1221_axis_top.v` 恢复 `IBUFGDS` 差分全局缓冲接入恢复时钟。
5. **测试向量更新**：`tb_8b10b_codec.v` TEST A/E 向量更新为标准值（K28.5=0x0FA、K28.0=0x0F4、D0.0=0x274、K28.5#2=0x305；TEST E 用 0x305/0x0FA）；TEST C 用 12 个合法 K 字符（0xEF/K15.7 非法 → 改 0xFB/K27.7）。

## 4. 仿真结果

### 4.1 8B/10B 编解码独立验证（`tb_8b10b_codec`）

| 测试 | 内容 | 结果 |
|------|------|------|
| TEST A | 已知向量：K28.5→0x0FA、K28.0→0x0F4、D0.0→0x274、K28.5 连发 RD 翻转→0x305 | **全 OK** |
| TEST B | 256 数据字符往返 + 独立 RD 合规检查 | **rd_violations=0，往返全通过** |
| TEST C | 12 个合法 K 字符（K28.0–7、K23.7/K27.7/K29.7/K30.7）往返 | **全通过** |
| TEST D | 非法 K（0x17=K23.0）→ enc_code_err；非法 10b(0)→ dec_code_err | **通过** |
| TEST E | RD− 下 c=4 码字(0x305)→disp_err；c=6 码字(0x0FA)→无 disp_err | **通过** |

**汇总：`pass=275 fail=0 rd_violations=0` → `RESULT: 8B10B TEST PASS`**（见 `codec_round2.log`）。

### 4.2 全顶层 CDC + 环回（`tb_tlk1221_full`）

| 项目 | 结果 |
|------|------|
| CDC：SYNC 异步翻转/毛刺后 `link_sync` 稳定 | **link_sync=1（同步器有效）** |
| 异步 FIFO 跨时钟域（user↔phy_tx、phy_rx↔user，频偏 8.0/8.02 ns） | 架构正确，无溢出/丢字 |
| 8B/10B 环回数据完整性 | **未通过**：mismatch=396，rx_data=5891≫tx=600 |

**未通过根因（非 8B/10B 编解码本身）**：`tlk1221_axis_user.v` 接收侧 RX 状态机未计入 `decode_8b10b`（REG_OUTPUT=1）的 1 拍译码延迟与 FIFO 读延迟，导致 `m_axis_tdata` 呈现滞后/重复值（实测 `got=0x78,0x78,0x78 / 0xf1,0xf1 / 0xe2…`），且 `rx_data` 远多于发送数。`code/disp_err=1` 来自测试用例中有意施加的 SYNC 毛刺（SYNC=0 期间 RD=0 → code_err），属预期，非设计缺陷。

> 注：第一轮该用例因 `rx_idx<tx_cnt` 比较保护而“假通过”（mismatch=0）；本轮 8B/10B 修正后暴露出此独立的用户层时序缺陷。

## 5. 缺陷状态与确认结论

| ID | 状态 | 说明 |
|----|------|------|
| 8B10B-1/2/3/4 | **已修复并验证** | 标准码表 + 分区算法，codec 全 PASS |
| LINK-1 | **已修复** | IDLE_WORD=0x0FA 标准 K28.5 逗号 |
| LINK-2 | **已修复** | 空闲 K28.5 交替 0x0FA/0x305，RD 平衡 |
| CDC-1 | **已修复** | phy_tx 域 3-FF 同步器 |
| CDC-2 | **已修复** | 恢复时钟 IBUFGDS |
| USER-RX-1（新发现） | **待修复** | `tlk1221_axis_user.v` 接收 FSM 未计入译码/FIFO 延迟，环回数据错位/重复 |
| TIM-1 | **建议** | 补充 XDC：`create_clock`（REFCLK/RBC0）、`set_input_delay`/`set_output_delay`（TD/RD 相对各自时钟）、`set_clock_groups -asynchronous`（三时钟域） |

**确认结论**：

- 本地 RTL 的 **8B/10B 编解码设计**（`encode_8b10b.v` / `decode_8b10b.v`）经标准码表替换与分区算法修正后，**完全符合 XAPP1112 / IEEE 802.3 基线**：256 数据字符 + 12 K 字符编解码严格互逆、RD 合规、K28.5 为标准逗号 0x0FA/0x305，独立仿真 **275/275 全通过、0 RD 违规**。
- 关联的链路层缺陷（IDLE 逗号、空闲 RD 平衡、CDC 同步器、恢复时钟缓冲）均已修复。
- 全顶层环回仍因 **用户层接收 FSM 时序缺陷（USER-RX-1）** 未通过，该缺陷与 8B/10B 编解码本身无关，建议下一步修复 `tlk1221_axis_user.v` RX 路径（按 `dec_dout` 有效时序对齐 FIFO 读与 AXI 输出）后重跑全顶层回归。
