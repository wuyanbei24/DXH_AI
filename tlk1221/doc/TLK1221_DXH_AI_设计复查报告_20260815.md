## 1. 复检方法

- 静态通读 5 个 RTL 模块（`tlk1221_axis_top / tlk1221_axis_user / tlk1221_phy_if / encode_8b10b / decode_8b10b`）。

## 3. 基于新前提发现的问题（按严重度）

### 3.1 【已确认-正确】时钟架构：TX 接口时钟与 REFCLK 的关系（最关键）

TLK1221 手册明确：**TD0–TD9 在 REFCLK 上升沿被锁存**，REFCLK 经 ×10 送串化器。即 FPGA 驱动 TD[9:0] 的寄存器**必须运行在 REFCLK（100MHz）这一网络**上。

当前代码：
```verilog
assign clk_phy_tx = clk_user;          // tlk1221_axis_top.v:114
```
**用户确认（q-0）**：`clk_user` 即那颗输出给芯片的 100MHz REFCLK（同一时钟网络）。→ `clk_phy_tx = clk_user` **正确**，TD 在 REFCLK 沿翻转符合手册。✅

> 前提约束：顶层必须把 `clk_user` 经 **BUFG** 引入本模块（该时钟现同时驱动 TD 寄存器、`xpm_fifo_async` 的 `wr_clk/rd_clk` 与 SYNC 同步器）。请确认顶层例化处已用 BUFG/MMCM->BUFG 提供 `clk_user`。

### 3.2 【已修复】XDC 时钟周期与 100MHz REFCLK 冲突

已重写 `xdc/tlk1221_top.xdc`：
- 周期 8.0 ns（125 MHz）→ **10.0 ns（100 MHz）**（用户给定 100MHz REFCLK；按手册 100MHz→1.0Gbps→RBC0=100MHz）。
- 移除对 `PL_SFP_CLK` 的 `create_clock`（该引脚现为 **FPGA 输出** 的转发时钟，方向错误已纠正）；TD 输出延迟改引用 **`clk_user`**（即真实发射时钟 `clk_phy_tx`）。
- `clk_rbc`（芯片恢复时钟，输入）保留 `create_clock`，周期 10ns。
- `set_clock_groups` 精简为 `clk_user` / `clk_rbc` **双域异步**（PL_SFP_CLK 不再作为时钟域）。✅

### 3.3 【已修复-高】PL_SFP_CLK（REFCLK 输出）未驱动 → 已补 ODDR

`tlk1221_axis_top.v` 原声明 `output wire PL_SFP_CLK` 但**从未驱动**（原 `IBUFG` 被注释），芯片将无参考时钟、链路必死。

**用户确认（q-1）**：100MHz REFCLK 由 **FPGA 内部 MMCM 生成后经 OBUF 输出**到芯片 REFCLK。

**修复**：在 `tlk1221_axis_top.v` 增加 `ODDR`（D1=1/D2=0，`C=clk_user`）将 100MHz 转发至 `PL_SFP_CLK`。
```verilog
ODDR #(.DDR_CLK_EDGE("SAME_EDGE"),.INIT(1'b0),.SRTYPE("SYNC"),.DRTYPE("SYNC"))
u_oddr_refclk (.Q(PL_SFP_CLK), .C(clk_user), .CE(1'b1),
               .D1(1'b1), .D2(1'b0), .R(1'b0), .S(1'b0));
```
ODDR 较裸 OBUF 更能保证输出 50% 占空比、无偏斜的干净转发时钟。✅

### 3.4 【已确认】线速率：1.0 Gbps @ 100MHz REFCLK ✅（TLK1221 支持 0.6–1.3 Gbps）

手册明确 0.6–1.3 Gbps。**"full-rate" 指 RBC 时钟模式（RBCMODE=高），不是 2.5 Gbps**。按 100MHz REFCLK×10 = **1.0 Gbps**，符合范围，本设计默认按此实现并已据此写 XDC（10ns）。

**用户已确认（q-2）**：目标线速率 = **1.0 Gbps @ 100MHz REFCLK**（符合 0.6–1.3 Gbps 范围）。设计、XDC 均已据此就绪，无需改 REFCLK/MMCM/ODDR 频率。

### 3.5 【已确认-符合预期】RX 侧 K 字符不向上层透传

`tlk1221_axis_user.v` 的 RX 路径 `m_axis_tuser` 恒为 0，所有 K 字符（含 K28.5）在 phy_if 被过滤、不通知用户层。

**用户确认（q-3）**：接收侧**无需透传 K 字符** → 当前实现符合预期。✅

> 说明：TX 侧仍允许经 `s_axis_tuser` 发送 K 字符（收发不对称），但既然 RX 不需识别 K，该不对称无功能影响，可保留。若后续协议要用 K28.5 做帧定界，再回填 RX 透传即可。

### 3.6 【低-中】TX 受 RX SYNC 门控的协议含义

`tlk1221_phy_if.v` 的 TX FSM 仅在 `tlk_rx_sync_tx`（RX 已对齐）后才发用户数据，IDLE 态持续发 K28.5 训练。当前实现自训练正常（IDLE 逗号训练对端），但意味着：**在 RX 链路未建立前，本端不会发用户数据**。对"纯发送方先发"场景会暂歇。请确认协议是否允许 TX 独立先于 RX 发送。

### 3.7 【低】ENABLE / LOOPEN 等芯片控制脚

本模块未涉及 TLK1221 的 `ENABLE`（低有效关断）、`LOOPEN`（环回）等控制。确认这些在板级/顶层已正确拉置（尤其 ENABLE 必须有效，否则芯片不工作）。

### 3.8 【低】差分 RBC0 缓冲

full-rate 模式下仅用 RBC0（RBC1 拉低）。当前 `BUFG(.I(PL_SFP_RBC0))` 对单端引脚直接全局缓冲。若板上 RBC0 是差分对（RBC0P/RBC0N），建议 `IBUFGDS→BUFG`；单端接法也可，但需确认 PCB 走线。

### 3.9 【低】位序需与 PCB pin 映射核对

TD/RD 总线按 `{bit9..bit0}` 映射，`enc_dout[9:4]=6b, [3:0]=4b`，与标准 TBI 一致；但需在板上确认 `PL_SFP_TD9` 等物理引脚与 TLK1221 TD9 一一对应（位序反接会导致整条链路数据错位）。
